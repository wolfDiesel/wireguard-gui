# ADR-0014 — Установка AWG-бэкенда из приложения

**Статус:** accepted
**Источник:** `skills/wireguardgui-wireguard/`, `skills/wireguardgui-architecture/`
**Связано:** ADR-0004, ADR-0013

## Контекст

AmneziaWG ставится пакетами вне стандартных репозиториев: COPR `amneziavpn/amneziawg` для Fedora/RHEL,
PPA `amnezia/ppa` для Debian/Ubuntu, репозиторий ALT Linux для ALT. Без этих пакетов функция AWG в
приложении мертва, а ручная установка требует знать, какое семейство дистрибутива у пользователя,
и помнить команды. Пользователь просил вкладку в настройках с проверкой, установкой и ручной инструкцией.

Установка пакетов — привилегированная операция: приложение получает root и выполняет shell-скрипты.
В проекте уже есть единственный механизм привилегий — долгоживущая pkexec-сессия (ADR-0004), и
обойти его (`sudo`, запуск внешних скриптов) нельзя.

## Решение

- В «Настройках» появляется вкладка **Amnesia**: статус бэкенда, версия инструментов и транспорт
  (`kernel module` / `userspace amneziawg-go`). Check и Install показываются только когда бэкенда нет.
- **Определение семейства** — `/etc/os-release` (`ID`, `ID_LIKE`), fallback на наличие `dnf`/`apt-get`;
  результат — `DistroFamily` (`Debian`, `Fedora`, `Alt`, `Unknown`).
- **Планы установки фиксированы в коде** (Infrastructure), по одному на семейство:
  - Debian: `apt-get update` → `software-properties-common gnupg2` → `add-apt-repository ppa:amnezia/ppa`
    → `update` → `apt-get install amneziawg` → `amneziawg-tools` (best-effort) → проверка;
  - Fedora: `dnf install dnf-plugins-core` → `dnf copr enable amneziavpn/amneziawg`
    → `dnf install amneziawg-dkms amneziawg-tools` → проверка;
  - ALT: `apt-get update` → `apt-get install amneziawg amneziawg-tools` → проверка;
  - проверка — `command -v awg && command -v awg-quick`, без неё установка считается неуспешной.
- Ни одна команда не собирается из данных UI: шаги — статические константы, пользователь выбирает
  только «поставить / не ставить».
- **Root** — только `IProcessRunner.RunPrivilegedShellAsync` (pkexec). Перед первым шагом установщик
  поднимает сессию (`true`), чтобы polkit спросил пароль до открытия прогресса; отмена авторизации
  возвращает `NeedsAdmin`, установка не начинается.
- **Прогресс** — `IProgress<BackendInstallProgressDto>` (номер шага, всего шагов, название, хвост
  вывода). Модалка не закрывается до завершения; при ошибке показывает шаг, вывод и кнопку ручной установки.
- **Неизвестное семейство** — план отсутствует, доступна только ручная инструкция.
- **Версия/транспорт** читаются без root: `awg --version`, наличие `/sys/module/amneziawg`,
  `modinfo -F version amneziawg`, наличие `amneziawg-go`.
- **Manual install** — модалка с командами для Debian/Ubuntu, Fedora, ALT и сборки из исходников,
  с копированием в буфер.

## Альтернативы

- **Только ссылка на документацию/терминал** — пользователь остаётся без установки и возвращается с вопросом.
- **Скачивать и запускать сторонние скрипты установки** — непроверяемый код от root; отвергнуто.
- **`sudo` вместо pkexec** — ломает ADR-0004, требует терминала и по-разному кэширует пароль.
- **Ставить только userspace `amneziawg-go`** — не требует DKMS, но отнимает выбор и добавляет зависимость.
- **Установка без прогресса (одна длинная команда)** — при сбое непонятно, на каком шаге всё встало.

## Последствия

+ Установка в два клика с понятными шагами и понятной ошибкой; версия и транспорт видны сразу.
+ Команды локализованы в одном месте и не зависят от ввода пользователя.
+ Ручной режим остаётся для неизвестных дистрибутивов и для случаев, когда пакеты ещё не обновлены.
− Приложение выполняет пакетные операции от root — поверхность риска больше, чем у обычного клиента.
− Команды придётся поддерживать при изменении пакетов у upstream (`amneziawg-tools` в PPA — best-effort).
− На ALT установка зависит от наличия пакетов в репозитории ALT; иначе пользователь уходит в ручной режим.
− Имена пакетов и smoke на живых системах (Fedora, deb-based, ALT) проверяются отдельным шагом.

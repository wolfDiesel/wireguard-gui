# ADR-0012 — Системная интеграция вынесена в отдельный проект Desktop

**Статус:** accepted
**Источник:** `skills/wireguardgui-architecture/`, Stage 6
**Связано:** ADR-0001, ADR-0002

## Контекст

Трей и хуки рабочего стола — Linux-специфичная интеграция, которая тянет нативные
зависимости и не имеет отношения ни к бизнес-логике, ни к доменной модели.

## Решение

Для системной интеграции рабочего стола существует отдельный проект `WireguardGui.Desktop`:
он зависит только от Application, а `App.Avalonia` использует его как порт.
Application и Domain не знают о существовании трея.

## Альтернативы

- Держать трей внутри UI-проекта — нативные зависимости проникают в UI, а App.Avalonia усложняется.
- Отдельный процесс-демон для трея — лишний процесс, синхронизация состояния, проблемы с автозапуском.

## Последствия

+ Нативная интеграция изолирована и не заражает остальные слои; её можно менять не трогая UI.
− Появляется ещё один проект в графе (и ещё одна связка, за которой следит PR checklist I5).
− Нативные вызовы хрупкие и зависят от библиотек конкретного дистрибутива — отладка тяжелее, чем у managed-кода.

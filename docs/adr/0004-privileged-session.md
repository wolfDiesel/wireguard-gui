# ADR-0004 — Привилегии: долгоживущая pkexec-сессия и единая точка `IProcessRunner`

**Статус:** accepted
**Источник:** `skills/wireguardgui-wireguard/`, [constitution](../../plan/constitution.md) I6
**Связано:** ADR-0003, ADR-0005

## Контекст

Подключение, split routing (`ip rule`, `nft`), `resolvectl` — десятки привилегированных команд
за одну сессию работы. Спрашивать пароль на каждую команду неприемлемо, а запускать приложение
целиком от root — нельзя.

## Решение

Все привилегированные операции идут через `IProcessRunner.RunPrivilegedAsync`:

1. `pkexec <command>`;
2. если euid уже 0 — прямой запуск;
3. отмена polkit маппится в понятное сообщение («Нужны права администратора»).

Авторизация выполняется один раз: команды сериализуются в долгоживущей привилегированной
сессии (root-хелпер), а не поднимают отдельный polkit-запрос на действие.

## Альтернативы

- `pkexec` на каждое действие — пароль по нескольку раз за операцию.
- Политика `sudoers`/`su` — требует ручной настройки системы пользователем.
- Отдельный привилегированный systemd-сервис с D-Bus API — правильнее по безопасности, но на порядок дороже в реализации.

## Последствия

+ Одна авторизация за сессию, единая точка логирования и маппинга ошибок.
− Команды в одной сессии сериализуются, а таймаута у сессии нет: зависшая команда подвешивает UI целиком (лечение — шаг 15-12).
− Экранирование аргументов полностью на нашей стороне: ошибка в сборке команды = инъекция через данные из сети (лечение — шаг 15-11).

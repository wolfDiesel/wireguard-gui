# ADR-0008 — Единственная точка доступа к `wireguard.conf`

**Статус:** accepted
**Источник:** `skills/wireguardgui-split-routing/`, [constitution](../../plan/constitution.md) I8, шаг 15-1
**Связано:** ADR-0001, ADR-0005, ADR-0009

## Контекст

Файл `wireguard.conf` меняют несколько подсистем: split routing (`AllowedIPs`, `Table`),
DNS-sync профиля, импорт и переподключение. Аудит зафиксировал гонки записи между
параллельными apply и save (пункт 6 анализа) — один writer перетирал правки другого.

## Решение

Все чтения и записи конфига идут через `IWireGuardConfigRepository`:
`ReadAsync` / `WriteAsync` / `UpdateAsync` под блокировкой. Прямые файловые операции
с `wireguard.conf` вне репозитория запрещены. `SplitRoutingConfigUpdater` и
`ProfileConfigDnsSync` переведены на него.

## Альтернативы

- Держать блокировку в каждом вызывающем — дублирование и легко забыть.
- Файловый lock на уровне ОС — избыточно для одного процесса-приложения.

## Последствия

+ Гонки устранены, нормализация конфига собрана в одном месте, поведение при параллельных apply предсказуемо.
− Репозиторий становится точкой сериализации записи: долгая операция держит остальных (при текущем объёме — приемлемо).
− Требует дисциплины: любой новый код, трогающий конфиг, обязан идти через репозиторий (иначе инвариант I8 обходится).

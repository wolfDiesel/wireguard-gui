# ADR-0010 — Результаты операций как DTO с кодом ошибки, а не исключения

**Статус:** accepted
**Источник:** `src/WireguardGui.Application/Services/ConnectionOutcomeResolver.cs`, [constitution](../../plan/constitution.md) Q2, шаг 10-21
**Связано:** ADR-0001, ADR-0003

## Контекст

Операции с сетью и системой могут завершаться «частично»: VPN фактически поднялся, но
команда вернула ненулевой код; либо split routing применился, но не всё. UI при этом обязан
показать локализованное сообщение, а не текст из stderr утилиты.

## Решение

На границе Application↔UI передаются DTO: `OperationResultDto`, `SplitRoutingResultDto`
с `OperationErrorCode`. Текст сообщения локализуется по коду ошибки. Отдельно учитывается
фактическое состояние: если соединение установлено, но команда сообщила об ошибке,
результат трактуется как успех с предупреждением — это делает `ConnectionOutcomeResolver`,
а не ViewModel.

## Альтернативы

- Пробрасывать исключения через слои — UI получал бы либо `Exception`, либо бессмысленный catch.
- Отдавать строки ошибок из утилит наружу — невозможно локализовать и хрупко.

## Последствия

+ Предсказуемая локализация (6 языков), нет «красного тоста» при реально поднятом VPN.
+ Один resolver-правило вместо разбора результата в каждом handler.
− Классификация опирается на фактическое состояние и текст команды — хрупко к изменениям вывода утилит.
− Набор `OperationErrorCode` становится публичным контрактом между слоями: добавление кода требует строк локализации во всех файлах.
